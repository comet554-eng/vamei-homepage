# 程序化科普短片 · 制作提示词（换账号直接用）

## 怎么用

1. 在新账号里新建任务，**先连接本机的 outputs 文件夹**（里面有 `trn_src`、`ang_src` 等现成代码，可直接当模板）。
2. 把下面「主提示词」整段粘贴进去，再在最后一行写上本次的题目或要求。
3. 也可以安装同目录下的 `science-film.skill`（点"保存技能"），以后只要说"按科普短片技能做一个关于 X 的视频"。

## 主提示词（整段复制）

你要为我制作一支原创的中文科普/知识类短片，用 Python 程序化生成画面和配乐，输出 1080p MP4。严格按以下规范执行。

### 一、工作流程（必须按顺序）
1. **先核实资料**：只用一手来源（论文原文或摘要、正史原文、官方文档）。论文优先查 Europe PMC 的 REST API（`https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=...&format=json&resultType=core`）、arXiv（`arxiv.org/abs/...`、`arxiv.org/html/...`），古籍查维基文库。网页太大时会被存成文件，用 python 去掉 HTML 标签后检索关键词。只能读到摘要的，片中只引用摘要里明确写到的结论。查不到作者或卷号的，不要编造，只写能确认的部分（比如 DOI 或 arXiv 编号）。
2. **出叙事方案**，保存为 md：一句话知识点、"片中说法 ↔ 出处"对照表、算出来的例子（数字用 python 算，不要心算）、分段结构和时长、已知局限。然后**停下来等我确认**。如果我说"选题和配乐你自己来"，就跳过确认，直接做。
3. 确认后制作，交付时**必须附上标题（首选 1 个 + 备选 2 个）和约 150 字的视频描述**，并用 present_files 把文件展示给我。

### 二、内容与风格
- 讲透一个知识点；节奏要紧凑：每句字幕对应一个画面变化，句间停顿约 0.2 秒，转场不超过 0.4 秒。时长可以长一些，但内容不能删。
- 不堆术语、不用装饰动画顶替解释、不强行升华。简化的模型要在画面上标出"示意 · 简化模型"；传说类内容要标明"属传说"。
- 画面：深色底（约 #07090C），衬线中文字体 Noto Serif CJK SC（Bold 用于标题和字幕），1920×1080，30 fps。字幕在底部居中，关键词用 `{b|蓝}`、`{w|金}`、`{r|红}` 标记高亮。左上角放章节标签（大号数字或词，加细线、小字说明，必要时带真实比例尺），右上角放文献卡（期刊或年份、中文结论、作者，加一枚"文献"印章），左下角放模型说明。
- 所有曲线、半径、速度、颜色都由公式实时计算，不要手调。

### 三、技术管线（已验证可行，照做）
- 依赖：python3、numpy、pycairo、PIL、ffmpeg（libx264 + aac）。不用 scipy。
- 每个场景写一个函数 `sN(c, t, fi)`，`S N_DUR` 为时长。`render.py` 支持 `still 场景 t1 t2 …`（出拼图 PNG，用来检查画面）和 `video 场景 输出 起始帧 结束帧`。cairo 画布的 BGRA 原始数据通过管道交给 ffmpeg 编码（`-preset medium -crf 17 -pix_fmt yuv420p`）。
- **沙箱限制**：每次 bash 调用最多约 3 分钟，而且命令返回后后台进程会被杀掉。所以必须**按 300 帧一段切块，`xargs -P 2` 两路并行**，每次调用跑 4–6 段，已完成的段落跳过，再用 ffmpeg concat 拼接，最后核对每段的帧数。
- 中文字体：PIL 读取 `/usr/share/fonts/opentype/noto/NotoSerifCJK-Bold.ttc` 时用 `index=2`（SC）；cairo 的斜体用字体矩阵做倾斜来模拟。
- 配乐：numpy 合成（pad、bell、drone、鼓）加分块 FFT 混响，总响度约 −21 dBFS RMS。

### 四、配音（需要配音版时）
- 先写 `script.py`（每句字幕，加可选的朗读改写：数字、单位、公式改成读法），再写 `tts.py` 用 edge-tts **7.2.8**、`zh-CN-YunyangNeural`、`rate=+8%` **逐句串行合成**（每句间隔 0.8 秒，失败退避重试）。量取每句时长后生成 `timeline.json`，所有场景时长和字幕时间都从这个文件读取。
- edge-tts 一旦连续返回 403（微软限流），就改用按字数估算的时间轴（每秒 4.4 字，每个逗号加 0.25 秒）出无配音版，或者用本地 piper（`zh_CN-huayan-medium`）。
- 混音：人声 RMS 归一到 −17 dB，再用 `tanh` 软限幅（不要整体压低音量）。人声出现时配乐压低到约 0.26 倍；旁白下面的铃声降一个八度，避开 1–3 kHz。最后逐句在 1–3 kHz 频段检查人声是否比纯配乐高至少 6 dB。

### 五、质量检查（每次都做）
- 渲染前：每个场景抽 2–4 帧拼图检查，字幕、标签、图形不能互相遮挡，人物不能出画。
- 渲染后：核对总帧数和时长，从成片均匀抽 20 帧做拼图，亮背景上的字幕要放大看是否清楚。
- 回复里如实说明：查了什么、没能核实什么、哪些是示意计算。

## 常见问题对照

| 现象 | 原因 | 对策 |
|---|---|---|
| bash 超时 / 后台渲染消失 | 单次调用约 3 分钟上限，命令返回后后台进程被杀 | 300 帧一段，两路并行，分多次调用 |
| edge-tts 返回 403 | 版本过旧或被微软限流 | 升到 7.2.8、串行加间隔；仍失败就出无配音版或改用 piper |
| 配音被配乐盖住 | 铃声落在 1–3 kHz | 加深压低、铃声降八度，逐句检测 |
| 改不了 md 文件 | 文件正在被编辑器打开（`~$` 锁文件） | 另存为新文件名 |
| PMC / PubMed 打不开 | 反爬虫验证 | 改用 Europe PMC API、出版社网站或 arXiv |
| 曲线出现尖刺 | 对分段函数求导 | 改用光滑函数（cos²、smoothstep） |
